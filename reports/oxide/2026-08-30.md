[^fn1]: “Wherever LLM-generated code is used, it becomes the responsibility of the engineer.” [https://rfd.shared.oxide.computer/rfd/0576](https://rfd.shared.oxide.computer/rfd/0576)

[^fn4]: “for any public Oxide writing, not only must an LLM not be used to write, but it must be further true that the text not be read as LLM-authored” [https://rfd.shared.oxide.computer/rfd/0576](https://rfd.shared.oxide.computer/rfd/0576)
[^fn5]: Distinguishes public writing (blog posts, press releases, social media, public RFDs) where LLM must not write and text must not be detectable as LLM-authored (verified via Pangram); personal writing (chat, review comments, email) where LLMs must never write; and operational writing (system docs, RFP responses) where LLM-assisted generation is permitted but must be verified.
[^fn6]: contributor
[^fn7]: “LLMs should be used for review (and can be very helpful when targeted to look for a particular kind of issue), but that review should not be accepted as a human substitute.” [https://rfd.shared.oxide.computer/rfd/0576](https://rfd.shared.oxide.computer/rfd/0576)
[^fn8]: “when uploading a document to a hosted LLM (ChatGPT, Claude, Gemini, etc.), there must be assurance of data privacy—and specifically, assurance that the model will not use the document to train future iterations of itself” [https://rfd.shared.oxide.computer/rfd/0576](https://rfd.shared.oxide.computer/rfd/0576)
